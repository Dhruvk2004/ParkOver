How a payment will flow

App asks for an order→ Worker creates it with the secret key→ Razorpay checkout opens in the app→ Worker checks the payment signature→ Firestore booking marked paid

The Worker is a tiny free server on Cloudflare. It exists so the Razorpay secret key never sits inside the app, where anyone could pull it out of the APK.

Paying in test mode

Razorpay's checkout looks real but moves no money. In the UPI option, type one of these IDs to choose the result:

  • success@razorpay · the payment succeeds
  • failure@razorpay · the payment fails, so you can see the error screen

For cards, Razorpay publishes test card numbers in its docs: search "Razorpay test card details". Any future expiry date and any CVV work.

What I build once you're done

  • The payments-worker folder: create-order and verify-payment routes, plus a webhook route for later.
  • Razorpay checkout in the app, with the bay held while the driver pays.
  • Booking status set to paid only by the Worker, enforced in the Firestore rules.
  • Refunds for cancellations and "didn't come", through the same Worker.
All of this stays free: Razorpay test mode costs nothing, and the Workers free plan covers far more than a prototype will use.
